# User Profile / 需求之书 v0.2

## 我是谁

我是一个独立开发者型的 AI 产品创造者。

我不是只想“学编程”或“做一个 demo”，而是在用 AI Agent 建立一套可持续产出产品的系统：发现需求、找开源参考、快速改造、做 MVP、包装产品、测试发布、做 SEO/Reddit 增长，再把过程沉淀成 Skill 和工作流。

我的核心身份更接近：

- AI 产品实验者
- 独立开发者
- 产品化驱动的工具创造者
- 想用 AI 放大执行力的人
- 正在训练自己和 AI 共同工作的系统搭建者

## 我正在做的主线

我当前真正的主线不是单个项目，而是：

把外部机会、开源项目、用户痛点、AI 能力和自己的想法，快速转成可卖、可用、可传播、可继续进化的软件产品。

已体现出来的项目方向包括：

- VoiceSlate：AI 语音输入、Prompt 工作流、本地记忆、声纹、Android 输入法、商业化、官网、SEO、Reddit 增长
- SkillBook：把资料、项目、经验转成可审查、可进化的 AI Skill 系统
- 需求自动挖掘机：从 X / GitHub / 社区里找产品痛点和 SaaS 机会
- 小学看图写话：儿童教育、触摸交互、语音输入、低龄用户训练系统
- 游戏/动画：Remotion 节气动画、地铁跑酷类小游戏、电子宠物、UnityAI 探索
- 网站克隆/重构：参考成熟产品官网，快速生成可营销的前端页面
- Crypto/量化/挖矿：探索数据、套利、工具化、自动化收益机会

## 我的长期目标

我想建立一个“AI 驱动的个人产品工厂”。

这个系统应该能帮我：

- 找到真实需求
- 判断需求值不值得做
- 找 GitHub 上能复用的成熟项目
- 快速改造成自己的产品
- 做出能跑的 MVP
- 做好 UI、官网、SEO、内容和分发
- 记录失败、复盘经验
- 把每次项目经验沉淀成可复用 Skill
- 让我下一次做产品更快、更准

## 我的明显偏好

- 喜欢先找 GitHub 上已有产品/库，不喜欢从零硬造
- 喜欢完整 task，不喜欢空泛建议
- 喜欢能直接开工的 prompt、PRD、目录结构、命令和验收标准
- 喜欢一步一步执行，并且每完成一步标记状态
- 喜欢 MVP，但不是玩具 demo，要能走向产品化
- 喜欢本地优先、BYOK、可控、可迁移
- 喜欢真实可运行、可测试、可打包、可发布
- 喜欢把项目做成“产品闭环”，不是只堆功能
- 喜欢 AI 主动读文档、读代码、找参考、执行验证

## 我不喜欢什么

- 不喜欢只讲概念不落地
- 不喜欢 AI 只总结，不帮我判断
- 不喜欢过度设计
- 不喜欢没有商业闭环的功能堆叠
- 不喜欢看起来很厉害但跑不通
- 不喜欢没有测试、没有验收、没有发布路径
- 不喜欢 AI 擅自扩大范围
- 不喜欢 AI 不读项目就开始瞎改
- 不喜欢重复解释自己的背景和偏好

## 我的优势

- 产品嗅觉强，能看到“工具 + 场景 + 商业化”的连接
- 很会提出有潜力的大方向
- 对 AI Agent 工作流、Skill、记忆、Prompt 系统有长期兴趣
- 能敏锐发现 AI 协作中的问题，比如上下文污染、记忆膨胀、Skill 退化
- 愿意快速试错，不害怕让 AI 实际改代码、跑命令、打包、测试
- 对增长也有意识，不只停在开发：SEO、Reddit、官网、定价、发布都在考虑

## 我当前最需要 AI 补足的能力

1. 工程收敛能力：帮我把大想法压成第一版 MVP，避免越做越大。
2. 技术判断能力：帮我判断用什么库、什么架构、什么方案最适合当前阶段。
3. 深度调试能力：帮我做系统排查，而不是猜。
4. 产品化闭环能力：帮我从“能跑”推进到“可卖”。
5. 增长执行能力：帮我判断 Reddit 怎么发、SEO 怎么做、内容怎么写、用户痛点怎么找。
6. 知识沉淀能力：帮我把每次项目经验变成文档、Skill、SOP、测试清单。

## AI 和我协作时应该怎么做

AI 应该默认：

- 先读项目文档和历史上下文
- 新需求优先找 GitHub 参考
- 先判断范围，再执行
- 能做就直接做，不要只给建议
- 复杂任务要分步骤并标记完成状态
- 每一步要有可验证产物
- 重要修改前说明改什么
- 遇到商业化问题，要补齐闭环，而不是只写功能
- 遇到 bug，要先复现、看日志、定位根因，再修
- 对外部资料不要盲目吸收，要先判断是否适合当前项目

## 我的核心需求一句话

我需要的不是一个临时写代码助手，而是一个能和我长期协作的 AI 产品合伙型执行系统：能找机会、读项目、做判断、写代码、修 bug、做增长、沉淀经验，并且越来越懂我的产品方向和工作方式。

## 当前最重要的几个方向

1. VoiceSlate 产品化和增长
2. SkillBook / AI Skill 系统
3. 需求自动挖掘机
4. AI Agent 工作流沉淀
5. 教育类互动产品
6. 网站/内容/SEO/Reddit 分发
7. 用 GitHub 开源项目快速改造成可用产品

## AI 不该误判我的地方

我不是只想做“好玩的 demo”。

我真正想要的是：

- 能用
- 能卖
- 能传播
- 能复用
- 能沉淀
- 能越来越快地做下一个产品

所以 AI 不应该只追求功能完成，而应该一直帮我看：

- 这个东西有没有用户
- 第一版够不够小
- 能不能发布
- 能不能被理解
- 能不能维护
- 能不能沉淀成下次复用的 Skill
